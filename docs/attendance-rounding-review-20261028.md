# 秒・分の端数を確認する手順

現在の保存計算は、採用出退勤の経過秒を日別に分へ切り捨て、保存休憩分を差し引く。休憩の区間も個別に分へ換算される。原打刻と採用時刻の秒は保持する。同じHH:mmを編集画面へ戻して保存する場合も既存の秒を保持する。

この計算を給与上の端数処理として適切と確定した意味ではない。今回、過去の計算値・休憩・給与CSVは変更していない。最終合計だけの丸めへ切り替える場合は、給与担当が適用日と過去差額の扱いを決めてから別途実施する。

管理者専用の読取API `GET /api/admin/reports/rounding-review?targetMonth=YYYY-MM&employeeId=ID` で確認する。employeeIdは省略可能。対象は既存の給与期間（パート等は前月21日〜当月20日）と在籍期間で、日次・原本・帳票履歴・ファイルを更新しない。通常の認証トークン利用時刻の更新は別であるため、本番読取禁止の検証では使わない。

検算は採用時刻の秒から保存休憩分×60を引き、比較可能な行だけの秒を合計してから分へ切り捨てる。30日とも59秒の端数があれば1770秒、参考比較の差は29分になる。これは支給額の自動修正指示ではない。

移行元の実働、不完全行、保存分と計算が一致しない行は勝手に再計算せず、理由付きで比較合計から除外する。既知の保存分合計と欠損行数を別に返す。保存済み休憩区間の秒合計は参考値で、仮置きの自動休憩を実取得と扱わない。

[厚生労働省の端数処理の説明](https://www.startup-roudou.mhlw.go.jp/qa/zigyonushi/chingin/q2.html)は、月の時間外等の合計についての扱いと、日別処理を区別している。[静岡労働局の労働時間把握・賃金支払の案内](https://jsite.mhlw.go.jp/shizuoka-roudoukyoku/roudoukyoku/roudou/kantoku/newpage_00977.html)も参照する。確認日2026-10-28。秒を含めた具体的な園の給与規則、適用日、支給計算側の処理は未確定として照合する。
