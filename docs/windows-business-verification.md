# Windows打刻端末の診断と実機検証

診断機能の確認と、カードを使った実機合格は別に記録します。今回の別PCでの実打刻検証は「実機未実施」です。

## 診断の実行

1. 配布ZIPをOneDriveの外へ展開します。診断用パッケージには職員情報、端末秘密鍵、既存キューを同梱しません。
2. 実機を診断する場合は、その端末用の既存 `punchsettings.json` を使います。端末識別子・秘密鍵をチャットや共有資料へ貼らないでください。
3. `Diagnose.cmd` を実行します。または `StaffHub.PunchApp.exe --diagnostics --output <保存先>` を実行します。
4. `%LOCALAPPDATA%\StaffHub\PunchApp\Diagnostics` のJSONを確認します。バージョン、設定の充足、カードリーダー列挙、GETによるヘルスチェック、推定時刻差、未送信キューの状態を記録します。
5. `INVALID` / `UNREADABLE` / `MISSING` の件数は未確認です。0件へ読み替えません。破損キューは診断では移動・修復・再保存しません。

診断モードは通常ウィンドウ、打刻送信、自動再送、ハートビートを起動しません。カードUIDも読み取りません。通信の合格はヘルスチェックまでで、端末秘密鍵による打刻認証の合格ではありません。時刻差はHTTP Dateと通信往復時間からの概算です。

## 実機検証票（次回実施）

実行前に端末、担当者、対象職員、日付、既存打刻の有無、期待する出退勤、通知先を記録します。本番では業務上予定された打刻を対象にします。通信断・再起動・重複試験は専用環境で行います。

|順序|操作|合格条件・残す証跡|
|---|---|---|
|1|診断を実行|設定、読取機、サーバー疎通、時刻差、キューが確認可能。診断前後のキューハッシュ・更新日時が同一|
|2|カードを1回かざす|対象本人に1件だけ出勤記録。端末表示・管理画面・履歴が一致|
|3|同じカードを連続してかざす|連続読み取りが二重出勤にならない|
|4|予定した退勤を打刻|出退勤時刻、休憩、勤務時間、日付が一致|
|5|専用環境で通信断を再現|未送信として表示され、JSONキューに1件残る。成功表示しない|
|6|未送信のまま再起動|キューが維持される。診断を実行しても送信・書換えしない|
|7|通信を復旧|同じdedupeKeyで再送され、サーバーには1件だけ保存。成功後に該当キューだけ除去|
|8|受付成功後の応答だけ失う|再送しても重複しない。受信拒否・締め済みは成功扱いしない|
|9|専用環境で破損JSONを用意|診断はINVALID・件数未確認。元ファイルを保持|

カード番号・秘密鍵を除いた診断JSON、端末時刻、画面、対象日の勤怠ID、キューハッシュを、リポジトリとOneDriveの外に保管します。

## パッケージ再作成

`dotnet test src/windows-punch/StaffHub.PunchApp.Tests` の後、`dotnet publish .../StaffHub.PunchApp.csproj -c Release -r win-x64 --self-contained true -p:StaffHubDiagnosticPackage=true -o <OneDrive外の保存先>` を実行します。公開前に `punchsettings.json` が実設定ではないことを確認し、テンプレートと手順書だけを追加します。
